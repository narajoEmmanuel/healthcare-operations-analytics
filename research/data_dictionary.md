# Analytical Data Dictionary

This dictionary interprets the variables published in the CMS *Medicare Inpatient Hospitals — by Provider and Service* dataset. The descriptions paraphrase the [official CMS data dictionary](https://data.cms.gov/resources/medicare-inpatient-hospitals-by-provider-and-service-data-dictionary-0) and add analytical guidance for this project. They do not replace the publisher's definitions.

The published row grain is a hospital provider and MS-DRG combination within a reporting year. Because the source variables do not include a year field, the ingestion process will need to derive `reporting_year` from verified source metadata.

| Variable | CMS concept | Narrative interpretation | Analytical treatment |
| --- | --- | --- | --- |
| `Rndrng_Prvdr_CCN` | Rendering Provider CCN | The CMS Certification Number identifies the institutional provider that billed Medicare for the inpatient service. It is the principal facility identifier in the dataset and anchors comparisons across DRGs and reporting periods. | Preserve as text so leading zeros are not lost. Use as the provider key only after testing uniqueness, continuity, and year-to-year coverage. |
| `Rndrng_Prvdr_Org_Name` | Rendering Provider Name | The organizational name associated with the billing provider gives the CCN a human-readable hospital label. Names may reflect spelling, ownership, or branding changes without necessarily indicating a different facility. | Use for display, not as a relational key. Profile naming changes and duplicate names across CCNs. |
| `Rndrng_Prvdr_St` | Rendering Provider Street Address | The street address describes the provider's reported physical location and supports geographic identification of facilities with similar or repeated names. | Treat as descriptive text. Do not infer provider identity from the address alone, and expect formatting changes across releases. |
| `Rndrng_Prvdr_City` | Rendering Provider City | The city records the municipality in which the provider is physically located. It supplies readable geographic context but is not a standardized geographic identifier by itself. | Use for labels and location summaries. Combine with state and ZIP code when resolving ambiguous place names. |
| `Rndrng_Prvdr_State_FIPS` | Rendering Provider State FIPS Code | The state FIPS code is a standardized geographic code for the state containing the provider. It supports consistent linkage to external geographic reference data. | Preserve as fixed-width text because leading zeros are meaningful. Validate against the state abbreviation before geographic joins. |
| `Rndrng_Prvdr_Zip5` | Rendering Provider ZIP Code | The five-digit ZIP code locates the provider within a postal area and can support more detailed geographic grouping than state or city. ZIP codes are postal constructs rather than direct measures of hospital markets. | Preserve as five-character text. Do not treat it as a number or assume it defines a service area or peer group. |
| `Rndrng_Prvdr_State_Abrvtn` | Rendering Provider State Abbreviation | The two-letter state abbreviation provides a readable state identifier for the provider's physical location. | Use for state-level filtering and display. Reconcile it with the FIPS code and investigate inconsistent or missing pairs. |
| `Rndrng_Prvdr_RUCA` | Rendering Provider Rural-Urban Commuting Area Code | The RUCA code characterizes the provider's ZIP code using population density, urbanization, and commuting patterns. It provides context for rural and urban comparisons but describes the surrounding ZIP code rather than the hospital's operational complexity. | Treat as a categorical code, not a continuous quantity. Preserve the original value and validate group definitions before constructing peer categories. |
| `Rndrng_Prvdr_RUCA_Desc` | Rendering Provider Rural-Urban Commuting Area Description | The RUCA description translates the code into a readable commuting and settlement classification. It helps explain geographic context without requiring users to memorize the coding scheme. | Use as a descriptive label paired with `Rndrng_Prvdr_RUCA`. Avoid deriving causal conclusions from rural-urban classification alone. |
| `DRG_Cd` | Diagnosis Related Group Code | The MS-DRG code identifies a class of inpatient stays with related clinical characteristics and expected resource use. Within a reporting year, it defines the service category used to compare similar hospitalizations across providers. | Preserve as fixed-width text and pair with the reporting year because MS-DRG definitions can change. Use with provider CCN to test the expected row grain. |
| `DRG_Desc` | Diagnosis Related Group Description | The DRG description gives the clinical and severity-oriented label associated with the code, making the hospitalization category interpretable to analysts and decision-makers. | Use for reporting and service-line mapping. Do not use the description as a key, and validate changes in wording or classification across years. |
| `Tot_Dschrgs` | Total Discharges | Total discharges represent the reported inpatient discharge volume billed by the provider for the MS-DRG. The measure indicates activity, but it does not describe unique patients, capacity, length of stay, or clinical outcomes. | Convert to an integer only after validation. Account for CMS suppression of provider/DRG combinations with 10 or fewer discharges; an absent row does not imply zero activity. |
| `Avg_Submtd_Cvrd_Chrg` | Average Submitted Covered Charge | This amount is the provider's average charge for Medicare-covered services associated with discharges in the DRG. It reflects the hospital's charge structure and is conceptually different from payment, cost, revenue, or margin. | Convert to a decimal monetary type after checking parsing and missing values. Use charge-to-payment comparisons cautiously and never interpret the amount as realized revenue. |
| `Avg_Tot_Pymt_Amt` | Average Total Payment | Average total payment combines the MS-DRG payment with applicable teaching, disproportionate-share, capital, and outlier components. It also includes beneficiary cost sharing and qualifying third-party payments. | Store as a decimal monetary measure. Interpret cross-hospital variation in light of payment adjustments; do not treat it as Medicare's payment alone. |
| `Avg_Mdcr_Pymt_Amt` | Average Medicare Payment | Average Medicare payment represents Medicare's share of the MS-DRG payment, including applicable teaching, disproportionate-share, capital, and outlier components, while excluding beneficiary cost sharing and additional third-party payments. | Store as a decimal monetary measure. Use as the primary payment benchmark only with explicit acknowledgment that it is not standardized for all geographic and institutional payment factors. |

## Interpretation controls

- Codes and geographic identifiers should remain text until their formats and leading zeros have been validated.
- Monetary values are averages per discharge within a provider/MS-DRG observation; they are not totals. Any payment-contribution estimate must state its formula and limitations.
- Charges, total payments, and Medicare payments answer different questions and must not be substituted for one another.
- Full-file profiling is still required to verify types, nulls, uniqueness, ranges, suppression effects, and cross-year consistency.
